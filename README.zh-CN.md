# skillwright

[English](README.md) · **简体中文**

按同一套方法做出来的 agent skill，以及那套方法本身。

`-wright` 是英语里的「造匠」后缀 —— shipwright 造船、playwright 编剧、wheelwright 造车轮。这里的每一个
skill 都是**设计出来的，不是收集来的**。这个区别就是这个仓存在的理由，所以它被做成可核查的：**每个 skill
都附一份「设计记录」，写明它背后的四个决定。**

本仓的 skill：[`skill-design`](skills/skill-design) · [`heuristic-evaluation`](skills/heuristic-evaluation)。
下面是它们为什么长这样。

## 321 字节能买到什么

Anthropic 的 `eli5` skill 只有 **321 字节**：一段 frontmatter 加两行正文。没有听众分级、没有类比库、
没有语气规范、没有示例、没有 checklist、没有任何代码。

它成立，是因为 `ELI5` 不是一句形容 —— 它是互联网上一个成熟的**解释体裁**，有专门的社区、固定的写法、
大量被点赞过的范例。叫出这个名字，等于把整套东西一次性调进来；而预训练里关于"这个体裁写好了是什么样"
的样本，比任何人手写的听众分类表都多得多。

**出处要说准，因为传播中普遍被简化**：它出自 Anthropic 的 Claude Code 团队工程师，通过
`anthropics/claude-plugins-community` 分发 —— 那是 Anthropic **托管的社区**市场。它**不在**任何一个官方
策展目录里（`anthropics/skills`、`anthropics/claude-plugins-official`）。员工作者 + 社区分发渠道。这个
区分影响的是你能期待多少维护承诺，不影响它作为设计样本的价值。

而它那两行正文，花的地方**都不在教怎么解释东西**：

1. **摘掉名字的副作用。** ELI5 按字面理解会招来幼儿语 —— 你不想让人用"想象你有一盒蜡笔"的口气讲你的
   鉴权模块。所以正文把听众重述为「对这个**话题**一无所知的人」：保留体裁的简化强度，摘掉年龄的字面义。
2. **钉住交付形态。** HTML artifact + 大图 + 极少文字。形态约束反过来干掉了剩下的活 —— 要塞进大图少字，
   就不可能堆术语和长段落。

commit 历史显示作者反复调的正是这两处，别的没动：`an idiot that knows nothing` → `someone who knows
nothing`，`in a HTML page` → `a HTML artifact`。而 frontmatter 里的 `description` **从头到尾没改过**。

所以杠杆住在 name 和 description（那也正是触发路由所看的位置），校正与形态约束住在正文。**两者不互相
稀释。**

## 杠杆的适用边界

**先征用，再重建。** 你要的行为若已有一个被广泛实践过的名字，就用名字，正文只花在摘掉它拖进来的东西上。

但有两个条件必须同时成立，而且它们是**独立的两个维度**：

- **信号强度** —— 模型到底见过这个词吗？公司内部名、个人自造名什么也不携带。
- **义项对齐** —— 一个词可以极其常见，却指向别处。`design tree` 在预训练里绝大多数指 CAD 的特征树，
  不是"设计决策的层级"。

**一个词可以信号极强而义项全错，这个组合最容易被漏掉** —— 结果是正文假设了一次激活，而激活跑去了错的
义项。

**这个杠杆对「判断类」比对「执行类」弱一档。** ELI5 产出一件东西，一个名字能调动整套实践，所以正文两句
话就够。而一个产出**结论**的 skill —— 这个页面好不好用、这个名字有没有在干活 —— 一个术语最多调动**单条
判据**，而**判据的组合才是那个判断**，若干决策的复合体很少有自己的名字。所以这类正文短不下来。

这不是写长的许可。两个动作能把它压住：

- **递归一次。** 整体没有名字，但你写下的每条判据自己有用词，而那些用词往往可以征用。`skill-design`
  就是实例：整体无名，但 `precising definition`、`stipulative definition`、`false trigger / missed
  trigger` 三处各自扛走了一段本该由正文解释的概念。
- **能拆就拆。** 若这些决策不必一起做，拆成几个各自能征用名字的 skill，胜过一个谁也征用不了的。

## 借来的协议会替你许下做不到的承诺

一个方法的名字会把它整套协议带进来，包括**单个 agent 满足不了的前提**。启发式评估假设 3–5 名独立评估者；
Nielsen 自己的数据是单个评估者只找出约 35% 的实际问题。**一个 agent 就是一个评估者。**

本仓的规矩：借来的协议若假设了不成立的条件，**skill 必须在自己的输出里说出来**，而不是记在旁边的笔记里。
否则一份看着干净的问题清单会被读成"这页没问题"。

## 四个问题

在写 skill 正文之前回答；对已经存在的 skill 同样可以反过来问：

1. **这个名字落在哪一档？**
   - ① 你要的义项是它唯一的义项 → 直接征用；正文只做两件事：摘副作用、钉形态
   - ② 你要的义项在它的义项集合里，但不是主导义 → 征用，并用一个从句把义项收窄
   - ③ 没有这个名字，或它的义项里没有你要的那个 → 写出可判定的判据，**不假设激活**；然后**递归一次**
2. **借来的名字拖进了什么你不想要的？** 用一句话摘掉。
3. **产物是不是比行为更容易描述？** 是就去约束产物。
4. **误触发一次和漏触发一次，哪个更贵？** 默认收窄。

最后：**看到一次失败再加约束，不要预先加。**

## 设计记录长什么样

| | |
|---|---|
| **情形** | ①／②／③，以及为什么不是另外两档 |
| **摘掉的副作用** | 借来的名字带进了什么、正文把它抵消掉 |
| **钉住的形态** | 这个 skill 必须产出的东西 |
| **触发宽度** | 宽还是窄，以及这个选择接受了哪一类错误 |

**这四行填不满的 skill，不该进这个仓。**

## 本仓的 skill

| Skill | 做什么 | 触发 |
|---|---|---|
| [`skill-design`](skills/skill-design) | 在写之前定下一个 skill 的名字、正文的职责和触发宽度；也可以反过来诊断已有的 skill。构建交给 `skill-creator` | 仅显式调用 |
| [`heuristic-evaluation`](skills/heuristic-evaluation) | 按 Nielsen 十条启发式与 WCAG 2.2 AA 评审已存在的页面，只报实际发现的违反 —— 并声明一个 agent 只是一个评估者 | 模型可调 |

每个 skill 目录里都有一份 `README.md`，承载它的设计记录、怎么看出它在生效、以及怎么看出它没生效。

## 准入门槛

- **正文只写给已经懂这个领域的模型。** 不写论证、不写置信度台账、不写给自己看的备注。**正文里唯一值得
  占位的理由，是那种"不给理由这条指令就会输给模型先验"的理由** —— 这正是 `Gotcha` 段的定义。
- **不成立的前提要写进输出**，不是写在脚注里。
- **看到一次失败再加约束**，不要预先加。
- **判据必须连着它的证据强度一起说。** 薄可以，不说不行。
- **不许自造方法论名字。** 造出来的词激活不了任何东西，却读起来像有权威 —— 于是谁也看不出是正文在干
  全部的活。

## 判据的证据强度

摊出来，供你权衡，而不是让你照信：

| 结论 | 支撑 | 强度 |
|---|---|---|
| 征用胜过重建 | 321 B 对一个同名的社区实现（约 8 KB，做的是同类事） | 较可靠 |
| ①②③ 三档划分 | 只有一个术语被完整走通；三档是断言，不是抽样得来 | 薄 |
| 钉形态能省字 | 一个实例，且可能只对"一次成型"的产物成立 | 薄 |
| 触发默认收窄 | 四个 skill 绑定显式调用，来自两位作者；有一个反例 | 中等 |
| 执行类 vs 判断类的边界 | 两个样本 | 弱 |

**你手上若有反证，以反证为准。**

## 安装

**尚未发布到 plugin marketplace。** 在那之前直接拷目录：

```bash
git clone https://github.com/maxzyma/skillwright
cp -R skillwright/skills/skill-design ~/.claude/skills/
```

项目级放项目里的 `.claude/skills/`，全局放 `~/.claude/skills/`。

**这里的 skill 是裸目录 + 一个 `SKILL.md`，不绑定 Claude Code** —— 把 `skills/<name>/` 拷进你的 agent
读 skill 的地方即可。frontmatter 里的 `disable-model-invocation` 是 Claude Code 的键，别的运行时会忽略
它，那时你只能显式调用 —— 而那本来就是这个键想要的效果。

## 范围

**只放 skill。** 常驻指令（`CLAUDE.md`、`.claude/rules/`）刻意不进：它们不是可安装的 plugin 组件，因此
无法通过 marketplace 做版本与升级；而且它们的价值大半在具体性 —— 本机路径、密钥策略、共享工作树前提，
一旦离开写它的那台机器就不再成立。
